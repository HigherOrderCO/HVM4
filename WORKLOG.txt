What Was Diagnosed About Missing AOT Speedup
--------------------------------------------
- Initial problem:
  - Most benchmarks showed little AOT speedup.
  - `mat_mul` generated C had many `aot_fallback_alo(...)` points.
- Key diagnosis:
  - Hot evaluation was deopting frequently due emitted branches that residualized terms.
  - DUP handling was a major source: prior logic only kept optimized flow under restrictive value conditions.
  - REF dispatch and APP spine handling in head compilation were incomplete, causing fallback-heavy paths.

Important Clarifications Discussed
----------------------------------
- HVM `let` in this lowering path appears as lambda application, which explains inner app shapes in core terms.
- “Head mode” corresponds to `aot_emit_node(..., head=1)`:
  - consumes APP frames from stack and keeps reducing at head.
- “Expression mode” corresponds to `aot_emit_node(..., head=0)`:
  - computes a subterm into a local `Term`.
- `aot_emit_is_closed(...)` is not for head-mode constructor matching.
  - It guards one direct `heap_read(arg_loc)` optimization in REF-call argument preparation so local binders are not captured incorrectly.
- User challenged vague naming; wording was corrected to concrete function/branch names.

ALO-DUP Semantics Clarified
---------------------------
- Discussed how ALO fallback can carry DUP-bound values through its captured environment.
- Clarified that DUP-bound values may need DP-tag reconstruction (`DP0`/`DP1`) when not copy-free.
- Clarified why “just keep compiling DUP body” is valid only if binder representation preserves semantics.
- Implemented path follows this model:
  - compile DUP body regardless,
  - use copy-free check only to choose binder representation, not control-flow deopt.

What Failed, and Why
--------------------
- Failed direction: broad constructor copy-free handling for dynamic values.
  - Symptom:
    - Broke DUP-sensitive tests (notably bound-var duplication semantics).
  - Root cause:
    - Treating dynamic constructor trees as copy-free is unsound under DUP semantics.
    - DP behavior and sharing identity matter for dynamic values.
  - Resolution:
    - Restrict constructor-tree copy-free acceptance to static heap only.
    - Keep dynamic terms non-copy-free unless trivially safe (`NUM`, `C00`).

- Requested strictness-analysis enhancement (from user) was not implemented in this patch set.
  - Reason:
    - scope was large (path-sensitive strictness through case-tree projections),
    - immediate blocker for mat_mul was deopt shape in DUP/call emission, which was addressed first.
  - User requirement retained:
    - do not change semantics by making argument evaluation globally stricter.

- Earlier mismatch during collapse-focused experimentation appeared in diff logs.
  - There was an observed output/perf mismatch in intermediate generated artifacts.
  - Final chosen code path was validated with targeted regression checks listed below.

What Worked, and Why
--------------------
- Worked: DUP body compilation now continues in compiled code regardless of value class.
  - Why:
    - DP-aware binder representation (`xN_is_dup`, `xN_loc`) preserves semantics for non-copy-free values.
    - Copy-free check now decides representation strategy, not “compile-or-deopt” control flow.

- Worked: direct REF dispatch and stack-range fast calls reduce overhead.
  - Why:
    - fewer generic fallback constructions for known compiled refs.

- Worked: static constant direct passing in REF args (when closed + static copy-free).
  - Why:
    - avoids unnecessary ALO residualization and environment capture cost for truly closed constants.

- Worked: contiguous allocations in `aot_fallback_alo` and ref-call frame setup.
  - Why:
    - reduced allocation overhead and improved locality.
